# Gateway API

Birga Gateway API предоставляет единый интерфейс для работы с подключёнными POS-системами (IIKO, R-Keeper, Poster). Все запросы маршрутизируются через Birga, который берёт на себя трансляцию протоколов, повторные попытки и маппинг данных.

## Базовый URL

```
https://api.birga-gateway.uz/api/v1
```

## Аутентификация

Все эндпоинты Gateway API требуют действующего Bearer токена в заголовке `Authorization`. См. раздел [Аутентификация](/ru/autorization/index) для получения токена.

## Общие заголовки

| Заголовок | Тип | Обязателен | Описание |
|-----------|-----|-----------|----------|
| `Authorization` | string | Да | `Bearer <access_token>` |
| `X-Request-Id` | string | Да | Уникальный идентификатор запроса (макс. 255 символов) |
| `Content-Type` | string | Да (POST) | `application/json` |

## Кэширование

GET-эндпоинты, возвращающие данные ресторана, филиала или меню, кэшируются. Используйте параметр `forceRefresh=true`, чтобы обойти кэш и получить актуальные данные напрямую из POS-системы.

| Группа | Описание |

| [Доставка](/ru/gateway-api/delivery/create-order) | Создание заказов на доставку |

## Формат ошибок

Все ошибки Gateway API возвращаются в следующем формате:

```json
{
  "code": "VALIDATION_ERROR",
  "path": "/api/v1/orders/create-order",
  "message": "branchId обязателен",
  "details": ["branchId должен быть валидным UUID"],
  "timestamp": "2024-01-15T10:30:00Z"
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `code` | string | Код ошибки |
| `path` | string | Путь запроса, вызвавшего ошибку |
| `message` | string | Описание ошибки |
| `details` | string[] | Дополнительные сведения об ошибке |
| `timestamp` | string | Время возникновения ошибки |
